# 21. Secinājumu un pielikumu melnraksts
Stundu apjoms pēc plāna: **1 h**.
## Secinājumi
Photo-only arhitektūra ļauj koncentrēt MVP uz foto savākšanu un galeriju.
Privāts storage un servera autorizācija ir nepieciešami neatkarīgi no UI.
Thumbnails un mediju optimizācija samazina ielādes apjomu.
Automatizētie testi palīdz atkārtoti pārbaudīt konstatētās kļūdas, bet
neaizvieto production konfigurācijas un fizisko ierīču testus.
## Pašvērtējuma pamats
Prakses laikā pilnveidota prasme sadalīt pilna cikla tīmekļa sistēmu atsevišķās
atbildībās, analizēt kļūdas pēc pārlūka un servera žurnāliem, veidot datubāzes
piekļuves noteikumus un pārbaudīt risinājumu reālās mobilajās ierīcēs.
Sarežģītākie darbi bija droša publiska viesa upload savienošana ar privātu
glabātuvi, laika zonu robežgadījumi un vairāku servisu deploy secība.
Nākamajā projektā staging vidi, automatizēto testu pamatu un monitoringu būtu
vērtīgi ieviest agrāk.
## Pielikumu saraksts
1. Prasības un datubāzes modelis.
2. Galveno plūsmu un arhitektūras apraksts.
3. Testēšanas pārskats un production pieņemšanas matrica.
4. Publiskās lapas ekrānattēli un pārbaudes JSON.
5. Darbināšanas instrukcija, SQL migrācijas un commit vēsture.
6. Faktiskā dienasgrāmata ar datumiem/stundām.
## Pirms iesniegšanas
Ievietot lietotāja gala veidnē, pārbaudīt rekvizītus un nodaļu numerāciju,
pievienot tikai reālus pierādījumus, noņemt neaizpildītos laukus pēc faktu saņemšanas.
Pirms iesniegšanas jāievieto praktikanta rekvizīti un elektroniskais paraksts.
## Dienasgrāmatas teksts
Sagatavots secinājumu un pielikumu struktūras melnraksts. Nodalīti tehniskie
secinājumi no personiskā pašvērtējuma un gala veidnē vēl ievietojamās informācijas.
